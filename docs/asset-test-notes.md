The Python suite separately regenerates the fixture and checks its exact bytes.

## Review findings

The initial build script bounded its first read, then reopened the asset with an
unbounded `fs::read`. Replacing or growing the file between reads could therefore
consume unbounded memory before revalidation. This was reported and the production
owner changed it to one bounded read whose exact validated bytes are staged.

The initial Python inspector omitted the Rust position/UV bounds and used a
different normal tolerance. The converter owner aligned both checks; independent
probes then rejected oversized position/UV values and accepted a Rust-valid 0.99
normal. The Rust contract tests explicitly cover those bounds. The Rust decoder itself
had no defect exposed by this review's tests.

## Limits

These tests establish parser/build contracts, not rendered model fidelity,
animation support, or exhaustive fuzzing. They do not establish rights to any
third-party content. VRMESH01 is a reversible layout: its CRC detects accidental
corruption, and provides neither encryption nor protection against extraction or
deliberate modification.
