# Pinned regenerated r15 admission

Original r15 admission is unchanged: camera sidecar v1 and pair receipt v2 require
original source SHA `cbed3051bb8c4bbdb78f72a49a7a51bd585db33636ddc5312dde38b05a2a86c4`.
Original r6 admission is also unchanged. Neither original path accepts a generated
source or an equivalence override.

A regenerated source uses `prone-entry-r15-camera-motion/v2` plus
`rust-duty-prone-camera-pair/v3`. Both contain the same `source_equivalence`
descriptor, with schema `rust-duty-prone-r15-regenerated-binding/v1`.
`candidate_sha256` is always the actual generated file hash; the original hash is
preserved separately as `approved_source_sha256` in the descriptor.

The reviewed invariant descriptor fields are stored in the small, hash-only
`prone_r15_equivalence_contract.json`, shared by Python and compiled into Rust.
They pin one exact recipe, approved witness file, full strict motion digest,
exact complete and legacy Action fingerprints, source producer code, non-Action
preservation digest, Blender version, reset, and clocks. No private geometry,
source arrays, evaluated matrices, or original soldier asset data are embedded.

Four additional descriptor hashes are run-specific: actual generated source,
strict comparison report, regenerated witness, and replay receipt. All must be
valid lowercase SHA-256 values. Generated source and witness identities must be
distinct from their original roles. The report must contain the measured full
motion digests and all reviewed pins, not just `passed=true`. Missing/stale proofs,
a different recipe or clock, or inconsistent receipt/sidecar descriptors fail
closed. A changed invariant requires a reviewed source revision.

Use the sampler with an explicitly pinned strict comparison report:

```text
blender --background --disable-autoexec generated-private.blend --python tools/sample_prone_r15_camera.py -- --output fresh-camera.json --source-equivalence source-equivalence.json --source-equivalence-sha256 <actual-report-sha256>
```

The sampler hashes the actual input bytes before and after its read-only work.
It never substitutes the original SHA for generated bytes. Without both optional
arguments, its original-source mode remains strict. The importer preserves the
checked descriptor into its receipt. The Rust loader checks the descriptor and
both companions, then caches that exact binding for capture telemetry.

This is an evidence-binding contract consumed by a trusted build/export pipeline,
not a cryptographic signature or a replacement for measuring the source. The
runtime cannot reopen BLEND or recompute evaluated source motion. The producer
must first strictly compare all 1,944 approved/regenerated motion samples; runtime
conversion, native rendering, and Windows acceptance remain separate checks.
A comparison report that lacks the newly measured digest fields is deliberately
ineligible for regenerated runtime admission.

## Source-free checks

```text
python -m unittest discover -s tools -p test_prone_r15_equivalence_admission.py -v
python -m unittest discover -s tools -p 'test_prone_camera_pair*.py' -v
cargo test --test prone_regenerated_contract
cargo test --test authored_prone_contract
```

Synthetic positive fixtures test the consumer's validation behavior only. They
are not proof that a real generated source, runtime artifact, or render passes.
