## Receipt and consumer interface

`admission.verify_stage(stage_context_path, context_sha256, context_package, receipt_sha256, terminal_sha256)` is read-only and returns the verified native envelope plus a derived `retained_process_validation` summary. The derived summary is not inserted into or substituted for the stored receipt bytes. Here context_sha256 is the SHA256 of actual stage-context file bytes; the envelope separately records canonical context_sha256 and context_file_sha256. Input callers must supply trusted hashes, not discover/trust a receipt's self-hash.

Envelope schema: `rust-duty-windows-native-stage/v1`. Its `binding` records mode, candidate/session/runner/run, approved_source_sha256, generated_source_sha256, canonical/grid, authored admission and host/build. Stages after export additionally bind actual_fbx_sha256. `output_files` maps relative POSIX names to `{sha256, bytes}`; `payload` is the measured native numerical report. Cross-platform float64 equality, runtime equivalence, artistic approval and activation remain false.

`admission.verify_gate(path, expected_sha, context_package)` verifies gate schema `rust-duty-windows-native-gate/v1`. `kind` is control, focus or conversion. Each `stages` entry has exact FilePin objects under `context`, `native_receipt`, `process_terminal`. Control is ordered control-export/control-full/control-bounded. Focus is ordered export/source-focus/focus-import; its export FBX identity is derived from the actual pinned output before comparing later bindings. Conversion is geometry followed by block indices 0–11. Conversion verification recursively checks actual target control/focus evidence. Missing stages, foreign candidates, wrong oracle/FBX/geometry hashes and cycles fail.

Source indices retain chronological frame-map insertion order and original source_rest_world, hierarchy, topology, projection and per-row paths/hashes, with explicit generated/approved identity fields. Rigid frame1 contains newly evaluated target geometry, original geometry-record fields, world matrices and complete float64/topology byte digests. Those raw native outputs are private runner-local evidence; none are included in this source package.

Runtime geometry and block files retain the unchanged streaming assembler's numerical payload schema, with source_sha256 explicitly meaning actual generated source and an added windows_provenance binding. A separate new Windows native envelope establishes their provenance. They are not rewritten Linux receipts. The existing unchanged `assemble_stream(..., contract=...)` is the final packaging API; frozen context v1's production entry remains blocked and is not called by this package. The parallel runtime consumer rechecks the 12 native block streams against actual candidate VRA bytes. This package alone does not create or admit a final assembled VRA, Rust sampler/game executable, Windows runtime parity or renderer capture.
