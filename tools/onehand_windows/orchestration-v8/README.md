# Windows orchestration v8: useful bounded child-failure diagnostics

Source-only successor to exact frozen orchestration-v7. The observed candidate d28af927b48e9f872386cf8f14ffaba2e8d2493a / Windows run 39112393401 failed with AdapterError and SHA256(child_exit_failure) 8819dbfbc52b2a15233f5fd2a3871087fa95fa56e351f62bd5fd46c11af8cb95. That result stays failed. This package cannot recover logs discarded at runner teardown and does not claim a cause for that historical failure.

The new failure_diagnostics.py helper is called only after Commands.run or Pipeline.native encounters an exception. Both boundaries re-raise the identical exception. Its bounded owned_failure field is additive to the existing public summary/v2; the original passed/error_type/error_sha256 remain unchanged, and success summaries keep their original shape. Early errors still identify a fixed command role/stage while marking receipt details unavailable.

The projector verifies expected argv, cwd, exact command context, host/environment/limits, supervisor Python and executable identities before publishing lifecycle details. It verifies the terminal seal, attempt/started/transport references and stream byte identities, rejects contradictory process lifecycle/linkage, and distinguishes failed, incomplete and completed child receipts without admitting native proof. Missing, changed, oversized, redirected, corrupt or request-mismatched data yields unavailable diagnostic fields. Self-seals establish local byte consistency, not host attestation.

Public output contains only fixed command/stage names, stage index, exit/completion/cleanup fields, safe fixed termination categories, and request/context/receipt/stream hashes plus byte counts. Both stdout and stderr can supply ordinary, Blender-prefixed, chained or bounded ExceptionGroup traceback locations. Only exact absolute paths matching one of 68 pinned original public Python source files can yield a public logical source ID, file hash and line number. Unknown paths/functions/source displays/locals/messages stay suppressed. Useful require/assert/raise templates come from rehashed pinned source AST, with dynamic expressions replaced by <dynamic>; a log message is emitted only when it exactly equals a static source declaration. Unknown dynamic log values never become public text. Recognized Rust error codes E#### are permitted; compiler message text is not.

Diagnostic bounds: receipt/context/source reads at most 1 MiB each; stdout 8 MiB, stderr 1 MiB, samples 8 MiB; 50,000 lines, 4,096 bytes per parsed line, 24 known frames and 8 traceback chains per stream; public projection at most 48 KiB. Oversize Cargo stdout, whose original command limits remain 16/32/64 MiB, makes receipt diagnostics unavailable rather than truncating it into a false verified identity. The normal native/source-replay stdout limit is unchanged at 4 MiB. An oversized public traceback projection drops traceback details while retaining bounded role/lifecycle/identity information. No traceback means no inferred Python cause.

Changed production siblings: owned_commands.py, host_tools.py, orchestrate.py, plus new failure_diagnostics.py and DIAGNOSTIC_SOURCE_PINS.json. source_checkout.py and the package-local workflow bind versioned orchestration-v8. DIAGNOSTIC_SOURCE_CHANGES.json reverses the exact declared edits and verifies selected files against actual v7 hashes; the historical v6 selection record is preserved separately. All admission checks, native/source recipe handlers, profile/art/replay/math/thresholds, installed tools and context/native/consumer/process packages remain unchanged.
