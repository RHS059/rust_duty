`portable_source.py` supplies only the missing CPU adapter. It accepts explicit paths for the existing package, baseline, approved source, original delta, output directory, Blender executable, Python executable and shared owner lock. It prints argv lists and never executes them. `inputs`, `plan` and `admit` all remain read-only. No default workspace, executable, download, upload or asset relocation is inferred.

Every file is verified before use. The three CPU core modules are freshly compiled from their just-verified source bytes; unpinned cached bytecode and altered in-memory modules cannot satisfy the code check. The adapter does not change the native producer's five-file identity or the frozen code/grid/correction files. The polygon optimization proposal is not adopted.

For future owner commands, the adapter rejects package-root caches and unexpected importable files/packages and emits Python `-I -B`. Native Blender already disables bytecode writes in the unchanged script. The owner must retain a controlled, cache-free package and recheck before launching; planning cannot stop another process changing files afterwards. Tool executable hashes are checked at planning, not attested by the old native receipt. The owner must record and recheck the trusted Python/Blender binaries immediately before and after execution. No installation, credential, permission or software-source trust is granted by these checks.

## Future Windows owner sequence

Use an already authorized trusted Python and Blender 4.3.2 installation. Resolve all paths on that Windows computer, including an owner-selected shared lock. Symlinks/reparse redirects and protected-input/output aliases are rejected. These commands are templates only; no Windows paths or tool hashes have been supplied or tested.

PowerShell variables below stand for actual owner-selected paths and verified executable hashes. The common argument list is ordinary PowerShell array syntax, not a shell command assembled from untrusted strings:

```powershell
$Common = @('--source-package', $Package, '--baseline', $Baseline,
            '--approved', $Approved, '--delta', $OriginalDelta,
            '--directory', $FreshOutput)
& $Python -I -B $Adapter inputs @Common
& $Python -I -B $Adapter plan @Common --python $Python --python-sha256 $PythonSha `
    --blender $Blender --blender-sha256 $BlenderSha --lock $SharedOwnerLock
```

1. Verify the adapter's own prepared pins and the package/input pins. `inputs` validates input bytes and recipe schema without creating the output directory.
2. `plan` initially emits a replay command using the existing delta. The native owner separately inspects/authorizes the argv, coordinates its shared queue, verifies binary/package pins and runs exactly that bounded job.
3. Repeat planning after each successful stage. It emits approved/regenerated witnesses for chunks 0–16, then the original CPU `seal` and `compare` commands. All 34 witnesses on the target platform must be new and bound to its actual generated source. No automatic retry or partial-output overwrite is permitted.
4. Separately retain the generated BLEND, replay receipt, witness index and final proof SHA-256 values from the controlled run. Supply those four expected pins to `admit`; do not manufacture expected values from unknown received files merely to make them pass.

```powershell
& $Python -I -B $Adapter admit @Common `
    --generated-source-sha256 $GeneratedSha --replay-receipt-sha256 $ReplaySha `
    --witness-index-sha256 $WitnessIndexSha --source-equivalence-sha256 $ProofSha
```

`admit` verifies actual input/output bytes, invokes the exact existing `verify_saved_equivalence`, rereads all 34 sealed witnesses, recomputes the complete proof and exact-compares the entire saved result. A completion flag, minimal summary, stale receipt/index, missing pair, mismatched source, changed paired hashes, changed numeric contract or changed producer cannot pass. Existing file presence alone yields `admission_required`, never a completion claim. Receipts go to stdout only; preserving their UTF-8 bytes and trusted hashes is the owner's responsibility.
