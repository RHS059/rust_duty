## Identities and closure

`RuntimeContext` has exact field/role inventories, immutable original invariants and lineage, distinct actual generated-source/FBX/runtime assets, native source-production host binding, and a distinct actual Windows Rust-build identity. Files must use ordinary paths, with foreign candidate/session paths, root overlap, aliases, hardlinks, symlink/reparse paths and Windows path ambiguities rejected.

The runtime candidate root is `private_root/session_id/candidates/candidate_id`. Proof outputs are `runtime-proof/`, sampler attempts are `process/runtime-{label}/`, and the exclusive owner lock is session-wide. No receipt is rewritten to a later context hash.

The build contract requires the complete current source-tree hash inventory with no subtree exclusions, including nested `.git` and `target`, exact original sampler and loader/math/build/Cargo pins, locked/offline target command, features, source revision/dirty-overlay identity, dependency source-root inventories and actual Cargo manifest/target membership, actual per-artifact rustc dep-info, generated-input hashes bound to the supervised Cargo process and observed OUT_DIR, compiler/toolchain provenance, actual rustc/cargo identities/version output, exact build receipt and stdout/stderr pins, and the fresh x64 PE sampler hash. Actual current Python executable and loaded Python DLL must match the native host manifest. Full source/dependency inventory is hash-only; nothing uploads it or private assets. Hashes/receipts establish consistency; authenticated build/run evidence remains the external trust prerequisite, not cryptographic attestation.

`OwnedProcess` launches the actual sampler directly, not a shell, wrapper or Cargo child. Its bounded JSONL iterator must be exhausted exactly. The caller rechecks terminal/stream evidence, exact argv, actual host/run/context, environment digest, executable before/after hashes, sample ordering/RSS/disk, cleanup and Windows Job emptiness. The 3 GiB bound is sampled direct-child working set, not an instantaneous/process-tree memory guarantee. Stage bounds remain 1,800 seconds, 0.2-second sampling, 3 GiB + 512 MiB initial availability and a 1 GiB disk floor. stdout is capped at 256 MiB, one row at 16 MiB, and the queue at two rows/32 MiB. Failed/partial records are preserved.

## Native invocation contract

See `NATIVE_INVOCATION.md` for exact role schemas and CLI order. No native invocation was run here. All receipt inputs require externally selected SHA256 values. Successful initialization always makes a new actual frame-1 sample and freezes bidirectional maps; later session validation reconstructs those maps from the retained actual frame-1 stream. Loading validates finite complete endpoint geometry; focus uses the same frozen mappings; chunks require focus first. Aggregate rejects partial, duplicated, reordered or mixed candidate/host/build/focus evidence.

Retirement is never automatic. `consumer.py retirement-plan` independently consumes the retained Rust stream and raw source rows a second time, verifies equality with measured records/maxima, and emits a nonmutating exact list. `retirement.py --execute-authorized` additionally requires that exact externally pinned plan and a separately verified authorization reference. The caller is responsible for obtaining the required user approval; a string is not itself authorization. Only the exact successful row/skin files may be deleted. Inputs, FBX/runtime, source descriptors, numerical/hash receipts, logs and failures are retained. Partial retirement is a failure and cannot be aggregated as success.

## Failure retention and privacy

Failure logs, exact input/tool pins and reproduction argv can be retained by the authorized hash-only CI route. Raw BLEND/FBX, geometry rows and sampler streams stay runner-local; this implementation has no upload route. Failed raw rows may be lost when that runner is torn down. Hash-only failure evidence is not a complete raw forensic backup. Existing separately backed-up approved originals/local failures are outside this package. No unavailable raw-upload/storage service is a required gate.
